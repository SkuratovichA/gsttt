# Proposal: Tell a value a site lacks from one it cannot read

## Why

A rule's value expression gave `None` both for a site that carries no such value and for a site that carries a value no connector could read as text, so the two were treated alike. The literal that stands in for a missing value then stood in for a value that was there too, and a prefix that was there but not text was read as no prefix. `APIRouter(prefix=settings.API_PREFIX)` served its routes at the path they were written with, `f('/x', options)` read the method `GET` of a rule `$arg2.method|GET`, a Flask `@app.route("/x", methods=METHODS)` was a `GET`, and `web::resource(PATH)` served `/`. Each of them is a contract at a path or method that nothing serves, which a graph that answers what a change affects must not draw.

## What Changes

- Core: a value expression is read to `Reading::Text`, `Reading::Absent` or `Reading::Unread`. `ValueExpr::eval` stays as the text of that reading, and `Prefix::reading` is the reading of a prefix, in place of `Prefix::read`, which gave a prefix that is not text as empty and has no caller left.
- Core: `Site::has_arg` becomes `Site::holds`, which says for any source of a value whether the site holds one it cannot read as text. A literal alternative stands in only for a value the site does not hold.
- Core: `Reading::as_prefix` is a reading as a prefix put in front of a path, read by the Python parse, the TypeScript analyzer and the Rust sites in place of a match each had of its own. `CallRule::behind` is the prefix a call is applied behind, with `serves_http` the rules that find the routes of an HTTP server, and the TypeScript and Rust connectors share it: a rule that is not an HTTP server's (a GraphQL resolver, say) is applied behind a prefix that is not text in both, where Rust alone made it a blind spot.
- Core: a decorator whose own `prefix` is unread is a blind spot, since joining nothing serves the contract at a path that is not its own.
- Python: a route on a router, a blueprint or a class whose prefix is not text is an unread site and serves nothing, unless the `url_prefix` of the Flask registration it is served through replaces that prefix. The link follows no way through such a router: a router included into it is served by no chain that passes it, and the include below it is an unread site. A mount whose prefix is not text is one unread site, and so is the include a cycle or a bound of the link stops a way at. A Flask `methods` that is not text is read as any method. A mount whose prefix is not text is tested before the bounds of the link, so a mount that closes a cycle is the one site the parse counted, under the name of the call it is written as.
- Spreads: an unpacking holds what it may give, so it is no longer read as a value the site lacks. In Python a `**mapping` among the keywords of a call holds a keyword it does not write, a `*iterable` holds the arguments at or after it, and a `**mapping` in a dict literal holds a key it does not write. In TypeScript a `...spread` among the arguments holds the arguments at or after it, and a `...spread` in an object literal holds a property it does not write. What a site writes as text is read as before, whatever the spread says. The Rust connector has no such construct and is not touched.
- Rust: a `web::resource` whose path is not text is an unread site and serves nothing. A client whose base is not text is read as before.
- TypeScript: implements `Site::holds` for an argument and a property of an argument. The prefix of a rule that serves routes on a receiver, made in the same file or in another, is read with `Prefix::reading` as the prefix of a `@Controller` is, and a call whose prefix is not text is a blind spot. The base of a client is read as before.
- The requirements "A literal alternative", "A decorator prefix that is not text" (`contract-formats`), "Prefixes that are not text", "Ways the link stops", "Unpackings" and "Flask routes" (`python`), "Actix resources that are not text" (`rust`) and "Receivers whose prefix is not text" and "Spreads" (`typescript`) get their scenarios.
- Versions: `FACT_FORMAT` goes from 12 to 13, because the rule code is not in the key of cached facts and an unchanged file would keep the facts read the old way. The Python connector goes from 1 to 2 and the Rust connector from 2 to 3, because what they hand the engine changes: a Python router keeps a prefix that is not text, a Rust resource that is not text yields no fact. `READER_VERSION` of the TypeScript connector goes from 7 to 8, because what it stores in the extra of a file entry changes: a shape records a spread, and a file cached with the old shape would be read as if it had none. The bump drops every cached file entry, its extra included.

## Impact

- Capabilities `contract-formats`, `python`, `rust` and `typescript`.
- `crates/core/src/rules.rs`, `FACT_FORMAT` in `crates/core/src/engine/keys.rs`, the Python and Rust connectors (`site.rs`, `parse.rs`, `link.rs`, `sites.rs`), and `Site::holds`, the spread of a shape and the prefix of a receiver in the TypeScript connector (`shape.rs`, `analyze.rs`, `project.rs`).
- A tree with no prefix, method or path that is not text, and no spread or unpacking, gives the same index as before. A tree with one gives fewer facts, each of them an unread site.
- The built-in output changes where a Flask route unpacks its options: `@app.route("/x", **opts)` serves any method, where it served `GET`, because the Flask pack is the only built-in rule with a literal alternative to a value. Checked against `17ec564`, the `axios`, `fetch` and NestJS rules on a call with a spread config (`axios({ ...config })`, `axios({ ...config, url })`, `axios.create({ ...cfg })`, `fetch('/x', { ...init })`, `axios(...args)`, `@Controller({ ...opts })`) and a FastAPI router built with `**options` give the same facts and unread sites as before. The spread changes what a pack of a project reads where it gives a value a literal alternative, such as `$arg2.method|GET`.
