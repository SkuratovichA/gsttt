# Proposal

## Why

gsttt is written in Rust and indexes itself first, and Rust services are the third side of the release promise. Rust's imports are paths through a module tree rather than file names, so the connector has to build that tree before it can resolve anything, and it has to follow paths written inline and inside macros, which is where much of real Rust code names its dependencies.

## What Changes

- The `rust` connector: projects per `Cargo.toml`, crate targets, workspace inheritance, parsing with `ra_ap_syntax` into module declarations, use trees, qualified paths (macro bodies included), includes, cfg flags and sites.
- The module tree per crate target, built in `prepare`, and path resolution through it, through `use` aliases and into workspace crates.
- Editions, 2015 when a manifest names none, dependency visibility per target, and `[lib]` names in resolution.
- Built-in packs in `crates/lang-rust/packs/`: `axum`, `actix`, `reqwest`, `sqlx`, `sea_orm`, `env`, with rules gated on the receiver the file shows and functions brought in by `use` found by their full path.
- `link` for axum `nest` and `merge` and actix `scope` across files.

## Capabilities

### New Capabilities

- `rust`: what the Rust connector reads, how it resolves, and which contracts it finds.

### Modified Capabilities

None.

## Impact

`crates/lang-rust/` only, plus new entries in the root `[workspace.dependencies]` if needed. Module imports carry no impact, as the queries spec says: a file depends on what it uses, not on the file that declares it.

### Known gaps

Reported as blind spots of every project:

- actix `configure`, tonic services and Diesel `table!`.
- Routers and clients passed as values the connector cannot follow, mounts written `Type::router()`, `nest_service`, and routers re-exported across crates with `pub use`.
- Router walks past 64 levels or 50000 visits, and crate targets past 10000 modules.
- Names that a glob import brings in, which resolve as an unknown package, and paths written inside `macro_rules!` bodies.
- Modules and routes generated by macros, and `include!` of generated code.
- A module declared twice under different `cfg`s, of which only the first is reached by name.

Not reported:

- Dev-dependencies are visible to every target but the build script, so non-test code that names one resolves to it instead of being an unknown package.
- A router that is mounted keeps its unprefixed routes as well, so `GET /{}` is listed beside `GET /api/bookings/{}` and a consumer calling the bare path matches a route the service does not serve. The engine keeps the unprefixed fact of a linked one (`crates/core/src/engine/pipeline.rs`), so this is a change in core for the integration.
- actix `#[route(method = "TRACE")]`, until core lists `TRACE` among its HTTP methods (`crates/core/src/rules.rs`).
- axum 0.7 wildcard paths such as `/*rest`, which core does not normalise to `{}`.
- Facade crates such as `shuttle-axum`: a pack applies only to a dependency the manifest declares itself.
- The functions a router reaches are matched by name within a file.
