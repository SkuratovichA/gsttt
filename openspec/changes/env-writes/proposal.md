# Proposal: Tell a write of a chain from a read, and let a write of an environment variable serve it

## Why

On a NestJS repository, 11 files were counted as readers of an environment variable that only set it. `process.env.X = …` and `process.env.X ??= …` in a test went through the same visitor as a read, so the chain rule named `env X` with the role `calls`. The same mistake makes `prisma.user.findMany = vi.fn()` a query of `table user`. A site that sets a variable is not a reader of it: the code that reads the variable depends on the setup that sets it, which is what the role `serves` says, and `impact` then reaches the readers from the setup that changed.

## What Changes

- `ChainRule` gets `written`, the role of a site that assigns to the chain. Unset, a write names nothing, which is how the Prisma and tRPC packs stay as they are. A new `Access` (`Read`, `Write`, `ReadWrite`) tells `ChainRule::apply` how the site uses the chain: a read names the key with `role`, a write with `written` and a read-write with both. A rule with no role for the access gives nothing, and a computed segment is one unread site whatever the access.
- TypeScript: the target of `=`, the argument of `delete`, a destructuring target and a `for…in` or `for…of` head are writes. A compound assignment and an update (`+=`, `??=`, `++`) are writes when they are the whole of an expression statement, and read-writes when their value is used. The chain that is the target takes the access, so `process.env[process.env.KEY] = 'v'` calls `env KEY` and leaves its own computed name unread. The `env` pack serves a written name and gets the call rule `vi.stubEnv("<NAME>", …)`. A write to a member of a Prisma client names no table.
- Python: a `Store` or `Del` subscript is a write, and so is the target of an augmented assignment. The `env` pack serves the names written by `os.environ[…] = …`, `del os.environ[…]`, `os.putenv`, `os.unsetenv`, `monkeypatch.setenv` and `monkeypatch.delenv`, and `os.environ.setdefault` and `os.environ.pop` call and serve the name. `pop` was not read before. A computed name that two rules match leaves one unread site for the call.
- Rust: the left side of `=` and of a compound assignment is a write. The `env` pack serves the names of `env::set_var`, `std::env::set_var`, `env::remove_var` and `std::env::remove_var`, inside `unsafe { }` as well.
- One `Pack::contracts` lists the kind and the role of every rule of a pack, and the provides of the three connectors are made from it in place of three lists of their own. The provides of an `env` pack now name `env serves` beside `env calls`, with the blind spots of what is not read: the aliases of the environment object, `Object.assign(process.env, …)`, `jest.replaceProperty(process.env, …)` and `process.env = {…}` in TypeScript, `os.environ.update(…)` and `os.environ |= …` in Python, and variable names built at run time in Rust.
- A new requirement `Writes of a chain` in `indexing`, `Environment writes` in `typescript`, `python` and `rust`, and `Writes to a Prisma client` in `typescript`. The requirements that exist keep their scenarios.
- Cache keys: `READER_VERSION` of lang-ts goes from 7 to 8, the `version` of the Python connector from 1 to 2 and that of the Rust connector from 2 to 3, because each now reads other sites for the same text. `FACT_FORMAT` stays: core makes the same key and the same outcome from the same text and the same access, and the connectors that now pass another access are the ones bumped. `LAYOUT` stays: no archived type changes shape. A pack without `written` hashes as before, because the field is left out when unset; the three `env` packs change, and so do their hashes.

## Impact

- Capabilities `indexing`, `typescript`, `python` and `rust`.
- `crates/core/src/rules.rs` (`Access`, `ChainRule::written`, `ChainRule::apply`, `Pack::contracts`) with the pinned pack schema in `crates/config`; `crates/lang-ts/` (the analyzer, the provides, the `env` pack, fixtures, tests and snapshots); `crates/lang-python/` (the parse, the provides, the `env` pack, tests); `crates/lang-rust/` (the chain sites, the provides, the `env` pack, fixtures, tests); `docs/architecture.md`.
- The coverage of a project that has the `env` pack lists `env serves` beside `env calls`, with the blind spots named above.
- `impact` on a file that sets a variable now reaches the files that read it: the generic rule of `queries`, a `serves` site reaches every file that calls the contract, is the one that does it (`Changing a server reaches its callers only`).
- Cost: `os.environ.update(…)`, `Object.assign(process.env, …)`, `jest.replaceProperty(process.env, …)` and `process.env = {…}` still set variables that no site serves. In TypeScript, `process.env.X.foo = 1` makes the whole chain the target of the write, so it serves `env X`; Python tells the nodes apart, so `os.environ["P"].foo = 1` calls `env P`.
- Indexes built by an earlier version are parsed again once.
