# Proposal: Record the declarations of Python files

## Why

The Python connector records no declarations, so `gsttt impact a.py --name foo` lists every importer of `a.py` for any name and follows the file whole, and `--changed` walks each changed Python file whole. TypeScript and Go answer the same questions by name: the importers that use `foo`, and the declarations that call a changed function. Python should answer them the same way, with the core walk that already works from the declarations a connector records.

## What Changes

- The Python connector records, for a file, its declarations with their lines (functions, classes, methods as `Class.name`, class variables, assignments, `self` attributes, `type` aliases and a `__main__` guard), what each declaration uses, what runs when the file loads, the members read on a value of unknown type, the names the file exports, and the classes whose members a name takes, as heirs and overrides.
- A file with a syntax error, and a file with a star import that reads a name nothing in it binds, record none of this and are followed whole, as a recovered Go file is.
- An import lists one name for each name it binds, so `from bookings import views as first, views as second` takes `views` twice and binds `first` and `second`. A `from` import is flagged as one that may name a module (`ImportFlags::MODULES`), and the walk reads such a name as the module itself when the file it reaches is that module, so `from pkg import sub` and `sub.foo()` reach `foo` in `pkg/sub.py`.
- A star barrel that lists the asked name among its own exports keeps its row, because a Python package declares names next to the ones it passes on, and one that declares the asked name itself, or re-exports it by name from another file as `export { helper } from './b'` does, yields to it: the name behind the star goes no further through that file. A declaration of the barrel that reads the name before it binds it again, as `INSTALLED_APPS = INSTALLED_APPS + [..]` after `from .base import *` does, is still listed.
- A name that a file exports itself, as `logger` in `app/logger.py`, is that name and not the module of the same stem, so `from app.logger import logger` and `logger.info()` reach the declaration.
- A local keeps the class it holds only up to the next binding of its name, by a loop, `with`, `except`, `match`, a walrus, `del` or another assignment, and a local bound to values of different types anywhere in its function holds none at any read. A member read on a builtin value (a literal, a comprehension, a call of a builtin type, or a name, parameter or field annotated with one) is no read of that member's name.
- A value has a class only when everything that gives it one names the same class: `Any`, a `TypeVar`, an alias of a union, a union of classes, `x or Dog()` and a field assigned two classes give none, so a member read on them is read by name. A member read on `self` stays a read when a base the file does not declare may hold the member.
- A string inside `Literal[...]` and in the metadata of `Annotated[...]` is no name. The first iterable of a comprehension is read where the comprehension stands, a class local to a function is an heir of nothing, and `X = wrap(X)` after `from m import X` uses the import, and so does the first binding of a top-level name in a file with a star import that reads the name, as `X = X + [1]` after `from .base import *` does.
- A module exports every name it binds at its top level, its imports among them, and the strings its `__all__` is given by an assignment, `+=`, `extend` or `append`, because `from m import x` takes an `x` that `m` only imports. A star import in the walk passes a name on whatever `__all__` of the file behind it lists, as before.
- The provides of every Python project name, as blind spots of the uses of a name, pytest fixtures, names that Django reads from a string, and functions replaced at run time.
- A Python file has a code for `--changed`, with comments and imports blanked and the indentation and the spaces of a string marked, so `--changed` names the changed function and reaches its callers, and not every importer of the file.
- Only Rust records no declarations now, so the requirements and the architecture notes that named Python say Rust.
- Versions: the `python` connector goes from 4 to 5, because its facts hold declarations, exports and the module flag, so the facts of every Python file are read again.

## Impact

- Capability `python`: the requirement "Names of an import" is replaced by one that lists a name for each name an import binds, because its one scenario names the dedupe that stops; declarations, uses, reads (builtin values included), where a local stops holding its type, comprehensions and local classes, strings in annotations, run on load, exports (every binding and every form of `__all__`), what gives a value its class, locals given different types, a name a star import may bring in, heirs, star imports, syntax errors, blind spots and the code of a file are new requirements.
- Capability `queries`: "Names in files without declarations" is replaced by a requirement that names Rust only, because a scenario of a modified requirement cannot be renamed or dropped; "A star barrel names nothing" is modified to keep the row of a barrel that lists the name; a name that may be a module, a star barrel that yields to a name it declares or re-exports by name, and one that lists the declaration reading the name it binds again, are new.
- Capability `cli`: "Languages without declarations walk the file whole" is modified to say Rust, and a changed Python function reaching its callers is new.
- `crates/core/src/fact.rs`, `crates/core/src/query/walk/names.rs`, `crates/core/src/text.rs` (the blanking of comments that Python and TypeScript share, now `crates/lang-ts/src/source.rs` calls it too), `crates/lang-python/src` (`symbols.rs`, `symbols/`, `code.rs`, `files.rs`, `project.rs`, `provides.rs`, `parse.rs`), `docs/architecture.md` and `plugin/skills/gsttt/SKILL.md`.
- A Python repository answers a question about a name with the files that use the name, and `--changed` with the callers of the changed functions. A question about a name that no import or call links (a pytest fixture, a string that Django reads, a monkeypatch) is told in the blind spots.
